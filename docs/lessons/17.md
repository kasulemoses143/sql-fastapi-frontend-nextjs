## Vocabulary

Validation: check and interpret incoming values. Serialization: turn data into a response representation. extra=forbid: reject unexpected fields.

## Explanation

The API should accept only editable fields. A student can supply a name and email but should not select their database id. Separate request and response schemas make this visible. Validation also prevents blank names, malformed emails, wrong types and unexpected keys.

Pydantic's model_validate can be practised without an HTTP server. ConfigDict str_strip_whitespace trims string input, but a min_length rule is still required to reject a blank result. EmailStr uses the email-validator dependency already in the course environment.

Server validation and database constraints complement each other. Validation provides useful input errors; database constraints protect against races and other clients. Neither is a replacement for authorization, which decides whether a caller may perform the action.

## Worked procedure

1. Save the complete file below as validate_demo.py in backend and run it with the environment active.
2. Try an invalid address and a whitespace-only name; observe ValidationError.
3. Add id=99 to the input and observe the unexpected-field error.
4. Compare this practice model to StudentWrite and StudentRead in the next lesson. The practice script is not imported by the API.

```python
from pydantic import BaseModel, ConfigDict, EmailStr, Field, ValidationError

class StudentInput(BaseModel):
    model_config = ConfigDict(str_strip_whitespace=True, extra='forbid')
    full_name: str = Field(min_length=1, max_length=100)
    email: EmailStr

for payload in [
    {'full_name':' Amina ', 'email':'amina@example.com'},
    {'full_name':' ', 'email':'not-an-email'},
]:
    try:
        print(StudentInput.model_validate(payload).model_dump())
    except ValidationError as error:
        print(error.errors())
```

## Independent practice

Why should StudentRead include id while StudentWrite does not? Does a type annotation alone stop an unauthorized user?

## Answer and reasoning

Try the task first. The server assigns id and reports it in responses. A type annotation describes data, not identity or permission. Authorization must be checked by server logic in a later protected design.
