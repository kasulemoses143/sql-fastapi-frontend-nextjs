# Lesson 04 Insert select update and delete safely

[Previous lesson](03.md) · [Next lesson](05.md)

## Learning objectives

Perform SQL CRUD; filter and sort records; use transactions to undo a change.

## Before you begin

Pass the preceding lesson's result check. Keep your files in student-project and these notes in course-reference. Complete only the setup sections directed by this lesson. Commit working code before replacing a complete file. A recovery checkpoint creates code in a new folder; it does not copy credentials or initialize database data.

## Vocabulary

CRUD: create, read, update, delete. WHERE: filter rows. ORDER BY: choose result order. Transaction: changes committed together or rolled back.

## Explanation

INSERT creates rows; SELECT reads them; UPDATE changes existing rows; DELETE removes them. UPDATE and DELETE without WHERE affect every eligible row. Start by writing a SELECT using the same WHERE condition to inspect the intended target.

A transaction begins with BEGIN. COMMIT makes its changes durable; ROLLBACK undoes its uncommitted changes. Rolling back does not guarantee IDs have no gaps. Never use a count of rows as the next ID.

The seed script is repeatable: ON CONFLICT skips records already present. This is different from the one-time schema script. Seed names are fictional.

## Worked procedure

1. Create and run 002_seed.sql below in the development SQL editor. Run it again and confirm it does not duplicate data.
2. Run the practice block below. Record the ordered results before and after the temporary update.
3. Use WHERE email = 'brian@example.com' to select Brian. Insert a fourth fictional student with a different email, then delete only that new record.
4. Complete the SQL foundations assessment in ASSESSMENTS.md independently.
5. Save the scripts in Git. The database password belongs in neither script nor commit.

```sql
SELECT id, full_name, email FROM students ORDER BY id;
SELECT code, credits FROM courses WHERE credits >= 3 ORDER BY code;
BEGIN;
UPDATE courses SET credits = 4 WHERE code = 'SQL101';
SELECT code, credits FROM courses WHERE code = 'SQL101';
ROLLBACK;
SELECT code, credits FROM courses WHERE code = 'SQL101';
```

### Complete file backend/sql/002_seed.sql

Create or replace `backend/sql/002_seed.sql` inside **student-project**. This is the entire file for this stage.

```sql
BEGIN;
INSERT INTO students (full_name, email) VALUES
('Amina Demo', 'amina@example.com'), ('Brian Demo', 'brian@example.com'),
('Carol Demo', 'carol@example.com') ON CONFLICT (email) DO NOTHING;
INSERT INTO courses (code, title, credits) VALUES
('SQL101', 'Relational databases', 3), ('API101', 'Python web APIs', 3)
ON CONFLICT (code) DO NOTHING;
INSERT INTO enrollments (student_id, course_id)
SELECT s.id, c.id FROM students s CROSS JOIN courses c
WHERE s.email = 'amina@example.com' AND c.code = 'SQL101'
ON CONFLICT (student_id, course_id) DO NOTHING;
COMMIT;
```

## Check your result

The seed gives 3 students, 2 courses and 1 enrollment. SQL101 credits return to 3 after rollback. Repeat seeding leaves the same logical data.

If the result differs, read the first error, confirm your terminal directory and environment, save the file and compare it with this complete example. Consult [troubleshooting](../TROUBLESHOOTING.md). Use an appropriately fresh development database when exact seed results are required; never reset valuable data to match a screenshot.

## Independent practice

Write a SELECT showing only course code and title ordered by code. Change API101 credits to 4 inside a transaction, inspect it, then undo it.

## Answer and reasoning

Try the task first. `SELECT code, title FROM courses ORDER BY code;` Then BEGIN; UPDATE courses SET credits=4 WHERE code='API101'; SELECT code,credits FROM courses WHERE code='API101'; ROLLBACK;. A SELECT after rollback shows 3 credits again.
