## Vocabulary

Database: organized persistent data. Table: records with a common structure. Row: one record. Column: one attribute. Primary key: unique row identifier.

## Explanation

A Python list disappears when a process ends unless you save it. A database persists independently of the program and can enforce rules when several programs use the same data. A student is one entity; a course is another. Do not store course names as a comma-separated string on the student: we will model their relationship explicitly.

Read this Python record: `{"full_name": "Amina Demo", "email": "amina@example.com"}`. In a table, full_name and email become named columns. Each row also receives an id. IDs identify records; a person's name does not, because two people can have the same name.

## Independent practice

List three entities in a library system. Give each a key and two attributes. Diagnostic: write a Python function that returns the emails in a list of dictionaries.

## Answer and reasoning

Try the task first. Library examples: books(id, title, isbn), members(id, name, email), loans(id, book_id, member_id). A possible diagnostic is `def emails(students): return [s["email"] for s in students]`. If dictionary access is unfamiliar, review it before Lesson 13.
