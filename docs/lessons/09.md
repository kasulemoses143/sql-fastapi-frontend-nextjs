## Vocabulary

Aggregate: calculation across rows. GROUP BY: rows to summarize together. HAVING: filter groups. COUNT(column): count non-NULL values.

## Explanation

A management screen often needs a summary rather than every row. Count enrollments for each course by grouping joined rows. A LEFT JOIN creates one unmatched row for a course with no enrollments; COUNT(*) would count that row, while COUNT(e.id) correctly reports zero.

WHERE filters input rows; HAVING filters the groups after aggregation. A transaction also matters when several writes form one business operation. For example, either create all related records successfully, or undo them when part fails.

## Worked procedure

1. Run the count query below against the current development dataset. Explain every number using the raw enrollment rows.
2. Add `HAVING COUNT(e.id) = 0` before ORDER BY to find empty courses.
3. Begin a transaction; insert a temporary course, inspect it, and roll back. Confirm the course is absent afterward.
4. Deliberately attempt a duplicate student/course pair. Read the database constraint name in the error.
5. Complete the relational SQL assessment, keeping the design task for Lesson 12.

```sql
SELECT c.code, COUNT(e.id) AS enrollment_count
FROM courses c
LEFT JOIN enrollments e ON e.course_id = c.id
GROUP BY c.id, c.code
ORDER BY c.code;
```

## Independent practice

Find students who have not enrolled in any course. Explain two correct approaches.

## Answer and reasoning

Try the task first. LEFT JOIN students to enrollments and filter `WHERE e.id IS NULL`; or GROUP BY student and use HAVING COUNT(e.id)=0. Both preserve students who have no matching enrollment.
