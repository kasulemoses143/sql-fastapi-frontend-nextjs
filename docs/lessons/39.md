## Vocabulary

Client Component: code with interactive browser behavior. Server Component: rendered by the server. Effect cleanup: stop obsolete result handling.

## Explanation

A component render should describe UI, not send a write request. useEffect can synchronize initial display data with an external API after a Client Component mounts. An event handler should perform a user-requested POST/PUT/DELETE. Mixing these responsibilities can cause duplicate writes.

A cleanup flag prevents an obsolete asynchronous response from updating state after a component is no longer active. AbortController is another option for canceling fetch work. Strict Mode can replay development effects; read-only loads should tolerate repeated calls.

The 'use client' directive defines a client boundary, not a secret-preserving boundary. NEXT_PUBLIC values are intentionally visible in browser bundles. Database credentials and privileged tokens never belong in client code. FastAPI is the only database-access application in this course.

## Independent practice

Why is storing DATABASE_URL in NEXT_PUBLIC_DATABASE_URL unsafe even when a page is a Server Component?

## Answer and reasoning

Try the task first. NEXT_PUBLIC explicitly makes values eligible for client bundling. Do not rely on a page designation to protect an intentionally public secret. Keep database configuration exclusively on the backend.
