## Vocabulary

Promise<T>: eventual result with type T. async: function returning a Promise. await: unwrap asynchronous result inside async. unknown: value requiring checking.

## Explanation

A network request cannot return data synchronously because the remote operation has not finished. An async function always returns a Promise, even when its code returns a simple object. await makes dependent steps readable without blocking the entire JavaScript runtime.

try/catch handles thrown errors and rejected Promises. fetch resolving does not establish HTTP success: check response.ok before parsing. A 204 has no body. JSON parsing can also fail when a server returns an HTML login page or an unexpected body.

In strict TypeScript, a caught value is unknown. A check such as error instanceof Error safely narrows it. Avoid replacing unknown with any just to access a property.

## Worked procedure

```typescript
async function getName():Promise<string> {return 'Amina';}
async function run():Promise<void> {
  try {
    const name = await getName();
    console.log(name.toUpperCase());
  } catch (error:unknown) {
    console.error(error instanceof Error ? error.message : 'Unexpected failure');
  }
}
console.log('start');
void run();
console.log('requested');
```

## Independent practice

What happens if you call getName without awaiting it and try to use toUpperCase on the result?

## Answer and reasoning

Try the task first. The result is a Promise<string>, not a string. TypeScript flags the missing string method; awaiting inside an async function obtains the eventual string.
