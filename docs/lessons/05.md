# Lesson 05 Filter sort and search records accurately

## Learning objectives

Combine predicates; use ILIKE and IN; handle NULL correctly; make result ordering explicit.

## Vocabulary

Predicate: condition for selecting records. AND/OR: combine conditions. ILIKE: case-insensitive pattern comparison. LIMIT/OFFSET: select a result window.

## Explanation

SELECT chooses columns while WHERE selects matching rows. Parentheses make combinations of AND and OR unambiguous. ILIKE is a PostgreSQL pattern match: % represents any sequence of characters. It is not the same as exact equality.

Rows have no guaranteed useful order unless ORDER BY requests one. Add a stable tie-breaker such as id when several names match. LIMIT/OFFSET without stable ordering makes paging unpredictable. Large offsets can become inefficient; keyset pagination is a later topic.

Our core tables do not permit NULL in required fields. The standalone expression below still demonstrates NULL semantics: NULL = NULL is unknown, while NULL IS NULL is true.

## Worked procedure

1. Run the queries below after the seed lesson. Observe how filtering and selecting columns are separate actions.
2. Change the name fragment to a value not present. An empty result is a valid successful query.
3. Add a second student with a similar name in a transaction, inspect the ordered results, and roll back so later examples retain their initial dataset.
4. Write one filter using parentheses to express a business rule in words before writing SQL.

```sql
SELECT id, full_name FROM students WHERE full_name ILIKE '%amina%' ORDER BY full_name, id;
SELECT code, credits FROM courses WHERE credits BETWEEN 1 AND 6 AND code IN ('SQL101','API101') ORDER BY code;
SELECT id, full_name FROM students ORDER BY id LIMIT 2 OFFSET 1;
SELECT NULL = NULL AS unknown_result, NULL IS NULL AS true_result;
```

## Check your result

The first query finds Amina; the third skips one ordered row and returns the next rows; unknown_result is NULL.

## Independent practice

Find courses whose title contains API or whose code starts with SQL, while requiring credits=3.

## Answer and reasoning

Try the task first. Use `WHERE (title ILIKE '%API%' OR code LIKE 'SQL%') AND credits=3`. Parentheses ensure the credits condition applies to both alternatives.
