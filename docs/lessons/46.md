# Lesson 46 Deploy the frontend and configure both origins

## Learning objectives

Deploy Next.js on Vercel; connect it to the existing API; verify production CORS and environment mappings.

## Before you begin

Pass the preceding lesson's result check. Keep your files in student-project and these notes in course-reference. Complete only the setup sections directed by this lesson. Commit working code before replacing a complete file. A recovery checkpoint creates code in a new folder; it does not copy credentials or initialize database data.

## Vocabulary

Origin: scheme, host and port. Preview: candidate deployment. Stable production URL: alias that remains across releases.

## Explanation

Two Vercel projects make the boundary between Python and frontend code visible. The backend was deployed in the backend deployment stage; now the frontend is deployed from the same GitHub repository with a different root directory. We do not reimplement Python routes in Next.js.

The production frontend's origin must appear in the backend's CORS allowlist exactly. There is no path or trailing slash in an origin. The frontend's NEXT_PUBLIC_API_BASE_URL is captured at build time and must point to the HTTPS API. Browser code cannot use localhost to reach a deployed backend.

## Worked procedure

1. Follow DEPLOYMENT.md sections D–F. Import the same GitHub repository as a new Vercel Next.js project with root frontend.
2. Set NEXT_PUBLIC_API_BASE_URL to the backend's stable production URL. Deploy and record the frontend's stable URL.
3. Add the exact frontend origin to backend CORS_ORIGINS, keeping localhost only if local work is still needed. Redeploy the backend.
4. Test from a fresh browser window, not only from a signed-in provider dashboard. Inspect preflight OPTIONS and the subsequent write request.
5. Use the preview policy in the deployment guide; do not grant CORS access to every *.vercel.app origin.

## Independent practice

Why can a 401 or login page from deployment protection look like a CORS error? Where should a bypass token never be placed?

## Answer and reasoning

Try the task first. The browser may receive an authentication response instead of the expected API response. Inspect the response and project deployment-protection settings. A bypass token must never go in NEXT_PUBLIC variables or browser source.
