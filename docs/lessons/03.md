## Learning objectives

Create three related tables; explain SQL types and constraints; reject invalid records.

## Vocabulary

DDL: SQL that defines structure. NOT NULL: value required. UNIQUE: no duplicate value. Foreign key: reference to an existing row. CHECK: permitted values.

## Explanation

Our relationship is many-to-many: one student can take many courses and one course can contain many students. Enrollment is the linking entity. It stores student_id and course_id, plus a date and status belonging to that relationship.

The database protects data even if a Python program contains a mistake. NOT NULL stops missing values; it does not reject an empty string, so names have a separate nonblank check. A unique student/course pair prevents duplicate enrollment. RESTRICT prevents deleting a parent while enrollments still reference it. We explicitly remove enrollments first.

The initial schema is a one-time migration. Running it twice should fail with an already-exists error. That protects us from silently assuming an unknown schema is correct.

### Complete file backend/sql/001_schema.sql

Create or replace `backend/sql/001_schema.sql` inside **student-project**. This is the entire file for this stage.

```sql
BEGIN;
CREATE TABLE students (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    full_name VARCHAR(100) NOT NULL CONSTRAINT student_name_not_blank CHECK (length(trim(full_name)) > 0),
    email VARCHAR(254) NOT NULL UNIQUE
);
CREATE TABLE courses (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    code VARCHAR(20) NOT NULL UNIQUE CONSTRAINT course_code_not_blank CHECK (length(trim(code)) > 0),
    title VARCHAR(120) NOT NULL CONSTRAINT course_title_not_blank CHECK (length(trim(title)) > 0),
    credits INTEGER NOT NULL CONSTRAINT credits_range CHECK (credits BETWEEN 1 AND 6)
);
CREATE TABLE enrollments (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    student_id INTEGER NOT NULL REFERENCES students(id) ON DELETE RESTRICT,
    course_id INTEGER NOT NULL REFERENCES courses(id) ON DELETE RESTRICT,
    enrolled_on DATE NOT NULL DEFAULT CURRENT_DATE,
    status VARCHAR(20) NOT NULL DEFAULT 'active'
        CONSTRAINT enrollment_status CHECK (status IN ('active', 'completed', 'withdrawn')),
    CONSTRAINT one_enrollment_per_pair UNIQUE (student_id, course_id)
);
CREATE INDEX ix_enrollments_student_id ON enrollments(student_id);
CREATE INDEX ix_enrollments_course_id ON enrollments(course_id);
COMMIT;
```

## Independent practice

Explain why enrollments needs two foreign keys and a unique pair. Draw the keys without looking at the schema.

## Answer and reasoning

Try the task first. Two foreign keys ensure both student and course exist. The unique pair stops a second row for the same student in the same course. Separate unique constraints on student_id and course_id would incorrectly prevent many-to-many enrollment.
