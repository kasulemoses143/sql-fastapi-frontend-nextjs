## Vocabulary

HTML: document structure. Tailwind: utility classes that generate visual styles. Promise: eventual result. await: wait inside an async function. response.ok: successful HTTP status range.

## Explanation

HTML describes headings, labels, inputs, buttons and tables. Tailwind utilities will style them in the Next.js build. A label associated with an input helps keyboard and screen-reader users. A form submit event must be handled to prevent a full-page navigation when TypeScript controls submission.

Network operations finish later, so fetch returns a Promise. await gets the eventual response inside an async function. fetch usually does not reject for 404 or 500: inspect response.ok. Network failures and blocked CORS requests can reject. Use try/catch to show an understandable message.

A browser page opened as a local file may send Origin: null and fail the API's CORS policy. Use the same-origin console demonstration in this lesson; the real frontend will run on localhost:3000 in the React foundations stage.

The fetch console exercise uses syntax that is valid in both JavaScript and TypeScript, without annotations. Browser DevTools executes JavaScript directly. All application source files in the course use TypeScript/TSX and the Next.js compiler.

## Worked procedure

1. Save the HTML example below as practice.html and open it locally. Submit the form and observe the default page behavior. This page has no API connection.
2. Inspect its semantic HTML; identify the label/input relationship and why type=email is only one validation layer.
3. Open your DEPLOYED API's /docs tab. In that tab's browser console run the plain browser-compatible async function below. Because it uses /students on the same API origin, this exercise does not need frontend CORS.
4. Change /students to /missing and observe the caught HTTP error. Do not paste secrets into the console.
5. Complete the TypeScript foundations assessment before introducing React.

```html
<!doctype html>
<html lang="en"><head><meta charset="utf-8"><title>Student form</title>

</head><body><h1>Add student</h1>
<form><label for="name">Full name</label><input id="name" name="full_name" required>

<button type="submit">Save</button></form></body></html>
```

Run this second block only in the console of your deployed API /docs tab:

```typescript
async function loadStudents() {
  try {
    const response = await fetch('/students');
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    const data = await response.json();
    console.log(data);
  } catch (error) { console.error(error.message); }
}
loadStudents();
```

## Independent practice

Explain why `const data = fetch("/students")` is not yet a student array. What does await response.json() do?

## Answer and reasoning

Try the task first. fetch immediately returns a Promise. Awaiting fetch returns a Response object; awaiting response.json() reads and parses its JSON body. Both are asynchronous steps.
