# Lesson 02 Choose data types and translate business rules

## Learning objectives

Choose PostgreSQL types; distinguish null from blank values; turn requirements into constraints.

## Vocabulary

Text: characters. Integer: whole number. Numeric: exact decimal. Boolean: true/false. Date: calendar value. NULL: missing or unknown value.

## Explanation

Choose a type from the meaning of a value, not only its appearance. A phone number is text because it may include + and leading zeros and is not added mathematically. Credits is an integer because fractional credits are outside this application's rules. Money should use an appropriate exact numeric representation rather than floating point.

NULL differs from an empty string and from zero. A required name should be NOT NULL and nonblank. SQL treats unknown values differently from ordinary values; predicates may evaluate to unknown. Use IS NULL to find missing values.

Requirements should become explicit rules: a student's email is unique, a course code is unique, credits are in the range 1–6, and enrollment refers to existing parents. Record these rules before creating tables. They guide SQL, API validation, UI feedback and tests.

## Worked procedure

1. Run the read-only expressions below in the development SQL editor. No tables are required yet.
2. Predict each result and identify its PostgreSQL type. Explain why a phone number should not be cast to integer.
3. Write a data dictionary with field, meaning, type, required status and uniqueness for our three entities.
4. Compare the dictionary with the next lesson's schema only after completing your own attempt.

```sql
SELECT 'Amina'::text AS name, 3::integer AS credits, true AS active;
SELECT NULL IS NULL AS missing, '' = '' AS blank, 0 = 0 AS zero_value;
SELECT '2026-01-01'::date AS example_date;
```

## Check your result

All statements return one row. Missing, blank and zero are different concepts, even when their simple checks each return true.

If the result differs, read the first error, confirm your terminal directory and environment, save the file and compare it with this complete example. ## Independent practice

Choose types for invoice amount, course title, registration number and enrollment date. State one rule for each.

## Answer and reasoning

Try the task first. Use numeric for an exact amount, text/varchar for a title and registration number, and date for enrollment date. A registration number is an identifier, so preserve leading zeros and add a uniqueness rule where required.
