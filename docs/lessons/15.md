## Vocabulary

HTTP: web request protocol. URL: resource address. Method: requested action. JSON: text format for data. Status code: response category.

## Explanation

A browser or another program is a client. FastAPI is the server application. A client sends an HTTP method and path, optionally with a JSON body. The server responds with a status and a body. GET requests read; POST requests create. Later PUT replaces editable fields, PATCH changes status, and DELETE removes a row.

A Python function is connected to an HTTP route by a decorator. Creating app = FastAPI() exposes the application object that Uvicorn and Vercel load. Defining a route does not start a server by itself.

## Worked procedure

1. Create backend/main.py using the complete short file below. This first version does not access the database.
2. From backend with the environment active, run `python -m uvicorn main:app --reload --port 8000`.
3. Open http://localhost:8000/health. Then open http://localhost:8000/docs. Expand GET /health, choose Try it out and Execute.
4. Visit /missing and inspect the 404 response. Explain why the server can be running while a particular path is missing.
5. Keep the server terminal open. Change the health message temporarily, save, observe reload, and restore the reference value.

```python
from fastapi import FastAPI
app = FastAPI(title="Student Course Enrollment API")

@app.get("/health")
def health():
    return {"status": "ok"}
```

## Check your result

GET /health returns status 200 and {"status":"ok"}. /docs shows the health route. /missing returns 404.

If the result differs, read the first error, confirm your terminal directory and environment, save the file and compare it with this complete example. ## Independent practice

Explain main:app in the launch command. Add GET /about returning {"course":"full-stack"}, test it, then remove it before the next checkpoint.

## Answer and reasoning

Try the task first. main is the main.py module; app is the FastAPI object inside it. A route can be added with @app.get("/about") above a function returning that dictionary. A 404 differs from a connection refused error: one is a server response, the other means the client could not connect.
