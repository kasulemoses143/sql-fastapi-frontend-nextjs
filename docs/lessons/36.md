# Lesson 36 State design immutable updates and derived data

## Learning objectives

Choose minimal state; use functional setters; derive counts from rows; distinguish state from a database.

## Before you begin

Pass the preceding lesson's result check. Keep your files in student-project and these notes in course-reference. Complete only the setup sections directed by this lesson. Commit working code before replacing a complete file. A recovery checkpoint creates code in a new folder; it does not copy credentials or initialize database data.

## Vocabulary

Derived state: computed from existing values. Functional setter: receives latest previous state. Mutation: changing an existing object in place.

## Explanation

Store the underlying information once. If rows is state, count is rows.length; storing both creates opportunities for disagreement. A filtered list can also be computed from rows plus a search string. Avoid copying the same truth into several independent states.

React may batch state changes, so setters using the previous value should use the functional form. Directly assigning rows[0].full_name does not create a new state value and may fail to render consistently. map/filter/spread express changes while preserving previous values.

Component state is not persistent storage. It is appropriate for form input, pending flags and fetched display data. PostgreSQL remains the persistent source of the actual student/course records.

## Worked procedure

1. Use the local student-card page from Lesson 35.
2. Add a derived count using rows.length; no additional state variable is required.
3. Read the functional remove setter and compare it with array mutation.
4. Practise the pure TypeScript update below in the Playground. Confirm the old object is unchanged. You do not need to replace application files for this example.

```typescript
type Student = {id:number; full_name:string};
const before:Student[] = [{id:1, full_name:'Amina'}];
const after = before.map(row => row.id === 1 ? {...row, full_name:'Amina Demo'} : row);
console.log(before[0]?.full_name, after[0]?.full_name);
```

## Check your result

## Independent practice

If you call setCount(count+1) twice in the same handler, why might it add only one? What is the reliable alternative?

## Answer and reasoning

Try the task first. Both calls may read the same rendered count. Use setCount(current => current+1) twice when each update depends on the preceding value.
