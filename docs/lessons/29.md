## Vocabulary

package.json: scripts/dependencies. package-lock.json: resolved dependency graph. tsc: TypeScript checker/compiler. Compile time: before execution.

## Explanation

A module exports values or types for another file to import. Use import type when only the type is needed. Types disappear from the executed output; functions and data do not. A default export is imported without braces, while named exports use braces.

The frontend package manifest describes scripts and direct dependencies. Its lockfile records exact resolved dependencies so npm ci can reproduce the intended install. npm install changes dependency resolution; npm ci follows the lockfile and fails if the manifest disagrees. Commit both.

Type checking cannot guarantee remote JSON matches a declared interface. Our API validates its output contract, while the frontend uses that known contract. When consuming an untrusted API add a runtime schema check, not just an assertion.

## Worked procedure

1. Complete SETUP F's Node installation only. Do not start Next.js yet. Confirm node and npm versions.
2. In course-reference/frontend run npm ci. This installs the pinned compiler and React types without installing global TypeScript.
3. Run the typecheck script below. Open tsconfig.json and find strict, noEmit and moduleResolution.
4. Read lib/types.ts and lib/api.ts. Identify a named type export, a type import and a generic function. You will write the UI after the language foundation assessment.

```sh
npm ci
npm run typecheck
```

## Independent practice

Why should someone cloning the course use npm ci rather than npm install next@latest?

## Answer and reasoning

Try the task first. npm ci preserves the reviewed dependency graph. Installing latest may introduce different behavior and setup prompts, making the lesson results harder to reproduce.
