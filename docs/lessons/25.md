## Vocabulary

const: binding that cannot be reassigned. let: reassignable binding. ===: strict equality. null: intentional empty value. undefined: missing value. Type annotation: a declared expected type. Inference: TypeScript determines a type. Compilation: transform TypeScript into executable JavaScript.

## Explanation

TypeScript adds static checking to JavaScript. Browsers execute JavaScript after the TypeScript syntax is removed by a build tool. Types help catch mistakes before running, but do not validate untrusted JSON at runtime. We learn the underlying language concepts and their types together; no previous JavaScript knowledge is required.

Use string, number and boolean for simple values. TypeScript often infers a type from the initial value, so write annotations where they clarify a boundary. Python type hints and TypeScript annotations both describe expected shapes, but the languages differ. Use const by default and let for reassignment. const protects the binding, not the contents of an object.

Python True/False/None correspond approximately to true/false/null, with undefined representing missing values. Use === for strict equality. Braces define blocks. Template literals use backticks and ${...}.

## Worked procedure

1. Open https://www.typescriptlang.org/play. Choose a new empty example and enable strict checking in TS Config if it is not already enabled. No local installation is needed for these foundation examples.
2. Enter the complete TypeScript block below. Read editor type information and then choose Run. The Logs panel shows the output.
3. Temporarily change count = 1 to count = 'one'. Read the type error, then restore the valid line. Explain that the error occurs before execution.
4. Compare an explicitly annotated variable with an inferred variable. Both are checked; annotation is not required on every local variable.
5. Save this example as values.ts in a notes folder. Do not paste TypeScript annotations into a normal browser console: that console executes JavaScript, not TypeScript.

```typescript
type Student = {id:number; full_name:string};
const student:Student = {id:7, full_name:'Amina'};
let count:number = 0;
count = 1;
function formatStudent(s:Student):string {return `${s.full_name} (${s.id})`;}
const add = (a:number, b:number):number => a + b;
console.log(formatStudent(student));
console.log(add(2,3));
console.log(count, typeof count);
```

## Independent practice

Write isPassing(mark:number):boolean and test 49, 50 and 80. Try passing a string and explain the editor error.

## Answer and reasoning

Try the task first. `const isPassing = (mark:number):boolean => mark >= 50;` gives false, true and true. A string argument is rejected by static checking. Runtime values from a form or network still need conversion and validation.
