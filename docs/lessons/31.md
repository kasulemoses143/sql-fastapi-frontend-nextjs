# Lesson 31 Semantic HTML and Tailwind foundations

[Previous lesson](30.md) · [Next lesson](32.md)

## Learning objectives

Read semantic HTML, use Tailwind utility classes, distinguish HTML class from TSX className, and preview responsive styling without writing custom CSS.

## Vocabulary

Semantic HTML describes meaning: headings, labels, navigation, tables and buttons. A utility class applies one styling decision. A variant applies a utility under a condition such as hover, keyboard focus or a screen breakpoint. Tailwind generates the required browser styles from the class names in source.

## Explanation

Our application uses Tailwind for all authored interface styling. You write utility classes on elements instead of creating selector rules. For example p-6 adds padding, rounded-xl rounds corners, bg-white sets a background and text-slate-900 sets text color. Tailwind is built on CSS, but this course does not ask you to author custom CSS rules.

Use unprefixed classes for the base small-screen layout, then sm: or md: variants to adjust at larger breakpoints. A class such as hover:bg-sky-800 changes a button on hover; focus-visible:outline-2 provides a keyboard focus indicator. Utility classes do not replace semantic labels or keyboard behavior.

HTML uses class="...". Typed React uses className="...". Keep that distinction clear when transferring a preview into a TSX component. Tailwind scans source for class names: use complete static names rather than building pieces such as bg-${color}-500.

## Worked procedure

1. Open [Tailwind Play](https://play.tailwindcss.com). Its browser playground already has Tailwind configured; do not install a CDN script in the application.
2. Replace the HTML panel with the complete example below. Leave the CSS panel at its default Tailwind entry; do not add custom rules.
3. Observe the preview. Explain each utility using the visual result. Change p-6 to p-8 and the heading from text-2xl to text-3xl.
4. Narrow and widen the preview. The base padding is 6 and the sm: padding is 8. Tab to the button and verify focus styling.
5. In Lesson 33 you install the actual Next.js Tailwind build integration and use className in TSX. A plain local HTML file with no Tailwind build does not interpret utility names automatically.

```html
<section class="mx-auto max-w-xl rounded-xl border border-slate-300 bg-white p-6 sm:p-8">
  <h1 class="mb-3 text-2xl font-bold text-slate-900">Student manager</h1>
  <p class="mb-5 text-slate-700">Manage fictional learning records.</p>
  <button type="button" class="rounded-md bg-sky-900 px-4 py-2 font-medium text-white hover:bg-sky-800 focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-amber-600">
    Add student
  </button>
</section>
```

## Check your result

A padded, bordered white panel with a readable heading and dark button appears. Padding responds to the breakpoint and keyboard focus remains visible. No custom CSS rules were written.

## Independent practice

Add a second action with a lighter background and dark text. Give it visible focus and explain its purpose without relying on color alone. Translate the HTML attributes into TSX syntax on paper.

## Answer and reasoning

A secondary action could use bg-slate-200 text-slate-900 hover:bg-slate-300 with the same padding and focus utilities. In TSX use className instead of class. A visible text label communicates the action; color alone does not.

## Tutor guidance and self study review

Ask learners to identify the semantic element first, then explain spacing, color, typography, state and responsive utilities. Keep the example small. Have each learner reproduce it and explain why the playground works while an unconfigured static file does not. Use the [Tailwind guide](../TAILWIND.md) for installation and the utility reference.
