## Vocabulary

Subquery: query inside another query. EXISTS: at least one matching row. Correlated query: references a row from the outer query.

## Explanation

Some questions are naturally expressed as existence: show students with at least one enrollment, or courses without any. EXISTS returns a true/false condition rather than duplicating a parent once per child. A correlated subquery connects its predicate to the outer row through an id.

Reports should begin with a plain-language requirement and a small hand-computed answer. Only then write SQL. This prevents a syntactically correct query from answering the wrong question. Include empty courses deliberately if the requirement says every course.

Do not assume one SQL shape is always faster. Correctness comes first; use EXPLAIN and realistic data when choosing between equivalent implementations.

## Worked procedure

1. Predict which seeded students have an enrollment. Run the first query below.
2. Run NOT EXISTS for empty courses and compare it with your LEFT JOIN answer.
3. Write a report of active enrollment counts per course, including courses with zero active rows. Put the status condition in the join condition if using LEFT JOIN.
4. Keep your expected results beside the query for assessment.

```sql
SELECT s.id, s.full_name FROM students s
WHERE EXISTS (SELECT 1 FROM enrollments e WHERE e.student_id=s.id)
ORDER BY s.id;
SELECT c.code FROM courses c
WHERE NOT EXISTS (SELECT 1 FROM enrollments e WHERE e.course_id=c.id)
ORDER BY c.code;
SELECT c.code, COUNT(e.id) AS active_count FROM courses c
LEFT JOIN enrollments e ON e.course_id=c.id AND e.status='active'
GROUP BY c.id, c.code ORDER BY c.code;
```

## Independent practice

Why does `WHERE e.status='active'` after a LEFT JOIN remove courses with no matching rows?

## Answer and reasoning

Try the task first. Unmatched child columns are NULL. The WHERE comparison is not true for those rows, so they are filtered out. Put the matching rule in ON to preserve all left-side courses.
