# Lesson 11 Indexes explain and incremental schema changes

## Learning objectives

Explain why indexes help selected queries; inspect a plan; practise a reversible ALTER TABLE migration.

## Vocabulary

Index: lookup structure maintained alongside a table. EXPLAIN: planned execution strategy. Migration: controlled schema change. Backward compatibility: old and new code can coexist.

## Explanation

A primary key and a unique constraint create supporting indexes in PostgreSQL. Foreign-key columns may also need indexes for joins and parent-delete checks; the initial schema explicitly adds them. Indexes consume storage and add write work, so do not index every field automatically.

EXPLAIN shows a query plan. A sequential scan on a tiny table is not a failure: reading a few rows can be cheaper than using an index. EXPLAIN ANALYZE actually executes a statement; use it deliberately, especially for writes.

Changing models.py later does not alter the database. Use an ordered migration, test it on disposable data, and plan how old/new code will read the schema. The rollback exercise here is a teaching experiment, not a production migration system.

## Worked procedure

1. Run EXPLAIN on the lookup below. Read scan type and filter; do not expect a particular plan on a tiny seed.
2. Run the reversible ALTER transaction below in development. Inspect columns before and after rollback.
3. Create a migration journal describing purpose, preconditions, SQL, verification and recovery for a future nullable phone field. Do not apply it to production.
4. Explain why automatic table creation at API startup is not a migration strategy.

```sql
EXPLAIN SELECT id, full_name FROM students WHERE email='amina@example.com';
BEGIN;
ALTER TABLE students ADD COLUMN phone VARCHAR(30);
SELECT column_name FROM information_schema.columns WHERE table_name='students' ORDER BY ordinal_position;
ROLLBACK;
SELECT column_name FROM information_schema.columns WHERE table_name='students' ORDER BY ordinal_position;
```

## Independent practice

Would an index on a boolean active flag always help? Why should schema rollback and application rollback be planned separately?

## Answer and reasoning

Try the task first. A low-selectivity flag may not improve typical reads; measure real queries. Rolling back application code does not automatically restore removed database data or columns.
