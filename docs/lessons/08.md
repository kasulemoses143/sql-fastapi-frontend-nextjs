## Vocabulary

Cardinality: allowed number of related records. Composite uniqueness: uniqueness across a set of columns. Cartesian product: every combination of two row sets.

## Explanation

Students and courses have independent identities. Enrollment connects them and owns status and enrolled_on. A single status column on Student would be incorrect because one student can complete one course while remaining active in another.

Join conditions must match the relationship keys. A missing condition can combine every student with every course, producing plausible-looking but false records. CROSS JOIN is useful when every combination is intentionally required, as in the seed script's filtered selection; it is not a replacement for a relationship join.

LEFT JOIN followed by WHERE e.id IS NULL finds parents with no matching child. Place filters carefully: filtering the child table in WHERE can discard unmatched rows and change the intended outer join.

## Worked procedure

1. Draw two students and two courses, then draw only the actual enrollment edges.
2. Run the two read-only queries below. Compare the real relationship rows with the deliberate CROSS JOIN combinations.
3. Run the unmatched-students query. Identify which seeded students have no enrollments.
4. Explain why storing names in enrollments would duplicate facts and create update inconsistencies.

```sql
SELECT s.full_name, c.code FROM students s CROSS JOIN courses c ORDER BY s.id, c.id;
SELECT s.full_name FROM students s LEFT JOIN enrollments e ON e.student_id=s.id WHERE e.id IS NULL ORDER BY s.id;
```

## Independent practice

Find courses with no enrolled students. Would a withdrawn record count as a relationship under the current model?

## Answer and reasoning

Try the task first. LEFT JOIN courses to enrollments and filter e.id IS NULL. A withdrawn row still exists and counts as a relationship; filtering only active enrollments expresses a different report.
